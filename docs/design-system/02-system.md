# مواصفات نظام تصميم إلمام CV

تاريخ الإعداد 20 نوفمبر 2026. النسخة المقترحة الأولى للمرحلة الثانية. اعتماد الشكل يتم بعد نموذج المرحلة الثالثة.

## الاتجاه

منتج مهني عربي بمساحات هادئة وتسلسل واضح، مع مشاهد حركية تعبّر عن إنشاء السيرة وتخصيصها والتقديم. تستخدم الرئيسية مساحة سرد أوسع، وتستخدم الأدوات كثافة مناسبة للعمل. تجمعهما مكونات وألوان وخطوط وحالات موحدة.

اقتراح المصمم هو البناء على أسود وأبيض إلمام والنعناعي/الأخضر الموجودين حاليًا. اللون التفاعلي يعبر عن الإجراءات والاختيار. يبقى شعار إلمام الأصلي هو مرجع العلامة. نتائج مهارة UI/UX Pro Max دعمت الهرمية الواضحة والتفاعلات القصيرة، واقترحت ألوانًا وخطًا عامًا مختلفين. اعتمدنا الهرمية والتفاعل، واخترنا الألوان الحالية والخط العربي المحلي لتناسقهما مع المشروع.

## الخط والمقاسات

Tajawal العربي واللاتيني المستضافان محليًا هما خط الواجهة. تستخدم الأوزان الفعلية 400 و700. تعرض الأرقام الحصص والرصيد بصيغة ar-SA وبعرض ثابت حيث يدعمه الخط. البريد والروابط والقيم المختلطة تستخدم bdi أو dir=auto.

## الشبكة والمساحة

- وحدة المسافات 4px، والسلم 4، 8، 12، 16، 24، 32، 48، 64، 96.
- حد المحتوى التسويقي 1280px، والقراءة 72ch. مساحة التطبيق تمتد إلى العرض المتاح.
- رأس التطبيق 72px على الكمبيوتر و64px على الهاتف. القائمة 248px، وتظهر قائمة مضغوطة عند ضيق العرض إلى 1024px. تحت 768px يستخدم تنقل الهاتف.
- القائمة ثابتة أسفل الرأس، وروابطها تتمرر داخلها عند قصر الشاشة. تذييلها ثابت داخل إطارها.
- بطاقات المؤشرات أربعة أعمدة ثم اثنان. بطاقات الخدمات ثلاثة ثم اثنان ثم عمود واحد حسب المساحة الفعلية.
- حواف 12px للحقول والأزرار، 20px للبطاقات، 24px للمشاهد. الدائرة للعداد والأيقونة عندما يخدم الشكل الدور.
- الجداول تتحول إلى صفوف ملائمة للجوال، مع تمرير داخلي عند الحاجة. لا يمتد التمرير الأفقي إلى الصفحة.

## الحركة

| الدور | المدة والسلوك |
| --- | --- |
| ضغط/تركيز/اختيار | 120–160ms |
| فتح قائمة أو بطاقة | 180–240ms |
| ظهور قسم | 360–480ms، إزاحة حتى 12px، مرة واحدة |
| تغيير رقم | 600ms عند وصول قيمة مؤكدة |
| مشهد شرح الخدمة | 4–8 ثوان، تشغيل عند ظهوره وإيقاف خارجه، تحكم إيقاف للتكرار |
| تحويل الوضع | 400ms عند دعم View Transitions، انتقال مباشر كبديل |

في reduced-motion تظهر الحالة النهائية فورًا. تعطل مؤثرات تتبع المؤشر على coarse pointer. يبقى المحتوى مقروءًا أثناء تحميل مؤثر أو فشله. تحريك الكلمات العربية يتم بالكلمة أو الكتلة الكاملة للحفاظ على اتصال الحروف.

## تركيب المصدر بعد اعتماد النموذج

تُنقل القواعد الأساسية إلى طبقة tokens ثم base ثم components ثم pages، ويكون للمكون تعريف واحد. تُضاف المكونات المحلية من سجل Magic UI إلى components/ui وتوضع تكيفات المنتج في مكونات مستقلة. يتطلب كل مكون فحص تبعياته وترخيصه ودعمه للعربية والحركة المخفضة قبل دمجه.

توجد React وTypeScript وTailwind وframer-motion وLucide بالفعل، مع alias @. تستخدم أمثلة Magic UI أحيانًا motion/react وnext-themes. يوحّد التنفيذ محرك الحركة مع الموجود ويصل تحويل الوضع بـ ThemeProvider الحالي. يستخدم Theme Toggler بديلًا مباشرًا عند غياب View Transitions.

تُراجع الأصول المستوردة من السجل قبل إدراجها. تبقى ألوان الحالة وحدود الحقول في الأساس المشترك، وتستقبل مؤثرات Magic UI القيم الدلالية من النظام.

## معايير اعتماد النموذج

- النظرة العامة والمساعد والقائمة يستخدمون نفس الأزرار والبطاقات والعناوين والحقول.
- الاختبار عند 390 و768 و1024 و1440px، مع شاشة قصيرة، وفي الوضعين اللونيين.
- تعمل لوحة المفاتيح والتركيز واللمس، ويظهر النص العربي كاملًا، وتعمل reduced-motion.
- ترتيب مهام المستخدم واضح، ويظهر أثر كل إجراء وحالاته، وتعمل روابط الخدمات.
- تعرض مؤشرات الرصيد والمسودات قيمًا من بيانات الحساب. حالات الرصيد صفر أو المنتهي أو المحمل حديثًا واضحة.
- يُقاس أداء النموذج مقابل النسخة الحالية قبل التعميم. تحمل مؤثرات الجسيمات والمشاهد الثقيلة عند ظهورها وتوقف عند إخفاء التبويب.
